# ai-cli-gateway 团队公告 · 2026-10-19

**ai-cli-gateway**（PyPI 包名，仓库 [ningL32/cli-gateway](https://github.com/ningL32/cli-gateway)）——统一 CLI 进程调用网关：让"AI 调 CLI 是否真跑、输出能否逐字核对"变得**可观测、可审计、可回放**。当前最新版本 **1.4.1**，已发 PyPI。

---

## 一、安装与升级

```bash
pip install ai-cli-gateway        # 首次安装
pip install -U ai-cli-gateway     # 升级
cli-gateway --version             # 验证（1.4.1 起支持）
```

> ⚠️ **版本号纪律（重要）**：PyPI 上的版本与 GitHub tag 一一对应（1.1.0 → 1.1.1 → 1.2.0 → 1.3.0 → 1.4.0 → 1.4.1）。如果你本机 `pip show` 显示的版本和预期不符：
> - **开发机 `-e` 可编辑安装**：其版本元数据是安装那一刻的快照，源码升版不会自动刷新——重装一次 `pip install -e .` 即对齐；
> - **干净环境装到旧版**：可能撞上 PyPI 索引同步间隙，指定版本重装 `pip install -U ai-cli-gateway==<版本>`；
> - **在仓库目录里 import**：会优先命中源码而非安装包——验证安装产物请换目录执行。

## 二、v1.1.0 → v1.4.1 变更摘要

| 版本 | 重点 |
|---|---|
| 1.1.1 | **行为变化**：CLI 退出码透传——超时 gw 退出码=124、命令未找到=127（旧版一律 1）；timeout 非法值 spawn 前拒收；修复 run() 真实返回被孙进程拖到无界的互锁挂死（实测 45.3s）；part 打开失败显式标记 truncated，观测层不再静默说谎 |
| 1.2.0 | **观测模式**：`--observe --task-id`，原子/元素/化合物模型（详见第四节），事件 sidecar `<log>.events.jsonl` |
| 1.3.0 | **类型化谱线**：事件从透传升级为语义类型 `system/text/tool_call/tool_result/reasoning/result/error`——对话树可重建 |
| 1.4.0 | **`task --tree`**：对话树渲染；编队实战产出（codex 实现 + claude 评审修复） |
| 1.4.1 | CLI `--version`（下游版本探测免 pip show 兜底） |

完整清单见仓库 [CHANGELOG.md](https://github.com/ningL32/cli-gateway/blob/main/CHANGELOG.md)。

## 三、快速上手

```bash
# 执行并全量落盘（-- 后的参数原样交给被调命令）
cli-gateway run --timeout 180 -- cmd /c claude -p "帮我看看这个报错"
# 屏幕输出：exit=0 duration=23300ms log=C:\Users\<你>\.cli-gateway\logs\...log

# 审计：列出与逐字回放
cli-gateway logs
cli-gateway replay <log路径>

# 环境体检：本机 9 个编码 CLI 谁能用、以什么形态调用
cli-gateway doctor            # --json / --no-probe / --only <命令>

# 观测模式：一次调用 = 一个原子；task-id 把多个原子绑成化合物（任务）
cli-gateway run --observe --task-id fix-login -- cmd /c claude -p "分析 diff"
cli-gateway run --observe --task-id fix-login -- codex exec -s workspace-write "修复"
cli-gateway task fix-login           # 原子清单 + 分子式（claude×1 + codex×1）
cli-gateway task fix-login --tree    # 对话树：谁在想、谁在改、工具调用全程
```

Python 库用法：`from cli_gateway import run, replay, read_events, task_atoms`（参数见 README）。

## 四、观测模式 30 秒理解（原子 / 元素 / 化合物）

- **原子**：一次调用。问（argv/prompt）与答（输出）成对出现、不可分割；exit_code + duration 是"结合完成"的证据。事件序列：`question → [note…] → answer → exit`
- **元素**：CLI 种类。周期表里 claude / codex 带**观测配方**，激发它们输出结构化 JSON 事件流（离散谱线）；其余 CLI 纯文本照常（连续谱）
- **化合物**：`--task-id` 绑定的原子图。**分子式** = 组成配比
- **守恒律**：原始日志是唯一真相，事件文件是派生解读，解析失败降级为全文 answer，绝不丢字

## 五、Windows 调用配方（真机实测 9/9）

| CLI | 调用方式 | 非交互语法 |
|---|---|---|
| claude | `cmd /c claude`（npm shim） | `claude -p "<任务>"` |
| codex | 直调 exe | `codex exec -s workspace-write "<任务>"` |
| kilo | `cmd /c kilo` | `kilo run "<任务>"` |
| mcode | `cmd /c mcode` | `mcode exec "<任务>"` |
| goose | 直调 exe | `goose run -i <文件>` 或 `-t "<文本>"` |
| opencode | `cmd /c opencode` | `opencode run "<任务>"` |
| qoder | 直调 exe（命令名 `qoderclicn`） | `qoderclicn -p "<提示>"` |
| crush | 直调 exe（WinGet 版自动命中） | `crush run "<任务>" --quiet` |
| hermes | 直调 exe | `hermes -z "<任务>"` |

**两条铁律**：① Git Bash 里 `cmd /c` 的 `/c` 会被 MSYS 转成 `C:\`——写 `//c` 或设 `MSYS_NO_PATHCONV=1`；② npm shim 类 CLI（claude/kilo/mcode/opencode）经网关必须 `cmd /c` 包装（CreateProcess 只认 .exe）。

## 六、下游项目集成须知（以 FdeHarness 为例）

- 适配器唯一耦合点：`lib/gateway.js`（版本清单 + KNOWN_FLOOR + 升级检查单维护在该文件头，**升级后按检查单登记**）
- 基础面（`run --timeout/--dir`、回显格式、落盘命名、超时杀树 124）自 1.1.0 起稳定兼容，1.4.x 零适配通过全套测试
- **升级注意**：1.1.1 起 CLI 退出码透传（超时=124，非 1）；1.4.1 起 `--version` 可直接解析，版本探测可下线 pip show 兜底
- 观测模式为增量能力：sidecar 与 `task` 子命令不影响既有包装逻辑，可按需接入

## 七、已知边界

- 观测模式 answer 事件含输出全文，适合中小输出；spawn 失败的调用不写 sidecar（raw 日志仍有完整记录）
- codex 工具类 item（file_change/mcp_tool_call 等）的字段映射部分为推测实现（宽容兜底，待真任务样本回填）
- 长任务建议 timeout ≥ 600s 并配 `--stdin-devnull`（防会读 stdin 的 CLI 挂起）
- 超时杀树大幅降低孤儿孙进程概率但非绝对保证，异常时结果置 `truncated=True` 并在日志尾部有 `# warning:` 行
